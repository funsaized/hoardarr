# Configuration reference

`hoardarr.yaml` is the user-owned configuration. Unknown settings are rejected. The executable
schema is [`src/config.ts`](../../src/config.ts); provider contracts live in
[`contracts.ts`](../../extensions/models/_lib/contracts.ts).

| Field                                     | Default / accepted values                                                              |
| ----------------------------------------- | -------------------------------------------------------------------------------------- |
| `schemaVersion`                           | `1` for demo/Compose/legacy; `2` for native guest                                      |
| `profile`                                 | `demo`, `compose-vpn-local`, `systemd-nordvpn-ssh`, `devvm-nordvpn-local`              |
| `paths.staging`, `.state`, `.library`     | Absolute, separate roots; no overlap or traversal                                      |
| `providers`                               | Named bindings for discovery, search, downloader, destination and network              |
| `providerFiles`                           | Absolute paths to additional provider descriptors                                      |
| `providerSettings`                        | Settings indexed by provider binding                                                   |
| `interests.movies`                        | `true`                                                                                 |
| `interests.region`, `.language`, `.limit` | `US`, `en-US`, `10` (1–100)                                                            |
| `interests.shows`                         | `[]`; entries contain `tmdbId`, `name`, and `category` (`tv` or `anime`)               |
| `policies.movie`, `.episode`              | Eligibility/ranking rules; see `extensions/models/_lib/policy.ts`                      |
| `download.seedTime`                       | `5m`; integer duration with optional `s`, `m`, `h`, `d`                                |
| `download.concurrency`                    | `4` (1–16)                                                                             |
| `download.timeoutSeconds`                 | `86400` (30–604800)                                                                    |
| `download.minFreeBytes`                   | 20 GiB; demo initialization sets `0`                                                   |
| `schedule.enabled`                        | `false`; native effective activation is preserved separately                           |
| `schedule.cron`                           | `0 2,8,14,22 * * *`; five fields, serve process local time zone                        |
| `torlink.binary`                          | Absolute Torlink CLI path; native requires `/opt/torlink/dist/cli.cjs`                 |
| `torlink.baseUrl`                         | `http://127.0.0.1:9161`; local daemon required                                         |
| `torlink.token`                           | Optional vault expression                                                              |
| `torlink.interface`                       | Tunnel interface binding; mandatory for native profile                                 |
| `tmdbKey`                                 | `${{ vault.get("hoardarr", "TMDB_API_KEY") }}`                                         |
| `host`, `ssh`                             | Required legacy host/SSH identity, paths and destination configuration                 |
| `guest`                                   | Protected native identity/storage mapping generated by provisioning; do not invent IDs |

Secrets use vault references in YAML, not literal values. For example:

```yaml
tmdbKey: '${{ vault.get("hoardarr", "TMDB_API_KEY") }}'
```

Use the hidden `swamp vault put hoardarr TMDB_API_KEY` prompt in the installation. API keys supplied
to unattended Swamp are private files or environment values, never committed source. Native
credentials live in `P/secrets/swamp.json` as `key` and `signinToken`, owned by the service identity
with mode 600. The root-owned guest identity and runtime policy are provisioner outputs.

Generated definitions can change with `apply`. Native apply requires stopped Swamp/Torlink/manual
writers and inhibits admissions. Native schedule intent is in `P/state/maintenance/activation.json`;
check `status` for the effective schedule.
